# Test modules that patch a first-party module, with the number of such patches in each.
#
# Format: `<repo-relative-path> <max_calls>`, one line per file, in `LC_ALL=C sort` order
# (codepoint order, which is what Python's own `sorted()` gives). The cap is 0: a
# `monkeypatch.setattr` on a first-party module pins that module's name into the test, so a
# module carrying any has no seam yet. Replace them with an injectable boundary object
# (scripts/deploy_tools/land_lib/tools.py + scripts/deploy_tools/tests/_land_fakes.py) and
# lower the entry; a file at 0 must lose its line. An entry may only fall or be deleted --
# that is enforced against origin/master, and it has to MATCH the count rather than bound it,
# so a test that sheds a patch lowers its line in the same PR.
#
# A path may be ADDED only when origin/master does not track the file (it is new, or renamed)
# or when the same commit changes the guard itself (a widened heuristic finds patches that
# were always there). Otherwise give the module a seam rather than listing the test. A commit
# that changes the guard may also RAISE an entry, for the same reason: a widening finds
# patches in a file that already has a line as well as in one that does not.
#
# The counting heuristic and its blind spots are in ansible/tests/_ratchet.py's module
# docstring.
#
# To see a file's count, lower its entry here by 1 and run the guard -- the failure names
# the real number:
#   uv run pytest ansible/tests/repo/test_module_length_ratchet.py -k no_test_module_patches
