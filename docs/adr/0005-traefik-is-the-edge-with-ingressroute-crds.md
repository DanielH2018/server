# ADR-0005: Traefik is the cluster edge, routed by IngressRoute CRDs

## Status

Accepted.

## Context

Under Docker, Traefik discovered services through container labels. The k3s migration
removed that: there are no Docker labels in a cluster and the docker provider is gone, so
every route had to be re-expressed. k3s also ships Traefik by default, so keeping it avoided
swapping the edge and the orchestrator in the same move.

The choice was between plain Kubernetes `Ingress` objects and Traefik's own `IngressRoute`
CRD. Everything the label-based routing encoded — the host rule, the entrypoint, the TLS
resolver and SAN set, the service port, rate limiting, optional forward-auth — maps onto
`IngressRoute` directly, and onto `Ingress` only through provider-specific annotations.

Around 33 services needed a route, so the per-route cost mattered more than the abstraction.

## Decision

Traefik is the edge. Routes are `IngressRoute` CRDs, generated by one shared Jinja macro
(`ansible/templates/ingressroute.yml.j2`) so that a service's route is a one-line call rather
than a hand-authored document.

The macro emits one host rule per service, adds a public name when the cluster-wide
`k8s_public_route` flag is on and the caller has not opted out with `public=false`, and
attaches the rate-limit middleware to everything.

## Consequences

**IngressRoute is a CRD, so ordering matters.** A service's entry must come after Traefik in
`containers_list`, because the play has no toposort and runs in list order. A route applied
before its CRD exists fails.

**An `https` route with no `tls:` block is a non-TLS router and never matches.** It applies
cleanly, `kubectl get` shows it, and Traefik logs nothing — the request simply falls through
to another router. That cost most of a day in 2026-08-07 and sent the investigation through
three dead ends before a field-by-field diff found it. A test now fails any rendered
IngressRoute serving `https` without a `tls:` block.

**The TLS block is explicit rather than inherited from the TLSStore default.** Omitting it
makes Traefik request a certificate per literal host rule — a separate issuance each, and
rate-limit arithmetic that no longer holds.

**The absent host rule is the guard, not DNS.** The Cloudflare wildcard resolves any name, so
a service is LAN-only because no public rule was emitted for it, never because the name does
not resolve.

**NetworkPolicy sees pod ports, not service ports.** Traefik's 80 and 443 are really 8000 and
8443, and fencing the wrong pair denies every in-cluster caller.

**`--dry-run` is what catches CRD mistakes.** Local rendering and schema checks have no
upstream schema for a CRD, so only a server-side dry run sees an invalid IngressRoute.

## Governs

No single line. `governs:` is empty; the decision is expressed by the shared macro.
